## 2. 默认架构方案（A，已固化进工程）

1. **用户自行安装** ZXDoc、ZLGCAN 驱动与 SDK；本产品只**检测并调用**已安装组件。
2. **厂商二进制零入库**：`.gitignore` 显式忽略 `vendor_sdk_local/`、`ZXDoc_um.pdf`、`ZXDoc_*.zip`、`*.dll`、`*.lib`、`kerneldlls/`（提交 942b7f9/f3ff97e 起生效，历史提交经核查无厂商文件）。
3. **松耦合集成**：ZXDoc 经正式第三方 API / Python 扩展接口；ZLGCAN 经独立 C++ Native Host 进程（P3）；不复制、不改造、不捆绑厂商内部实现。
4. **安装器只做检测**：缺组件时引导用户从官方渠道安装，不代下载/不重分发（PROD-01 范围）。
5. 违规兜底：CI/发布流程增加"厂商二进制扫描"（文件魔数 + 扩展名 + 已知 DLL 版本资源），命中即失败（PROD-04 落地项）。

## 3. 模型服务与数据政策（A）

| 项 | 政策 |

## 6. P0-05 补充发现（影响本结论）

1. **手册版本错位**：手册对应 ZXDoc V1.2.14-beta.5（2025-09-06），本地安装包为 V1.3.14-beta.1（2026-10-30）——许可条款是否随版本变化**需按目标版本复核**（V）。
2. 手册全文无 SDK/DLL 再分发专门条款（检索 0 命中）→ Q8 必须取得书面答复，不得以 LGPLv3 对产品软件的声明推及 SDK 二进制。
3. 第三方 API 无完整签名（16 项"待实测"）→ 1.1 版 ZXDoc Adapter 只允许占位/Mock，本文件不因手册描述而放宽集成方式。

## 7. 结论（当前可执行）

1. **可以继续开发与开源仓库公开**：现行架构与仓库内容不包含任何厂商二进制，许可风险受控。
2. **不可**在获得 Q8 书面许可前：把厂商 DLL/驱动/头文件/示例打包进安装包、镜像或发布物；不可宣称"与周立功官方合作"。
3. 本文件随 P0-05 证据回填与 Q8 答复升版；发布门槛（任务书 18.3）"许可与分发审查完成"以第 4 节清单全勾为判定。
