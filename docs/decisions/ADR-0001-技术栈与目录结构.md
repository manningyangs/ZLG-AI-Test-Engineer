# ADR-0001：技术栈与仓库目录结构（草案）

**状态：** Draft（待 P1 启动前人工批准）
**日期：** 2026-11-18
**依据：** 《Trae 可执行开发任务书 V1.0》第 2 章；本机环境盘点（repo_baseline.md 第 2 节）

---

## 背景

仓库当前为纯文档状态，无既有技术栈。P1 需要建立工程底座，需先确定技术栈与目录结构，避免后续无理由换栈。

## 决策（采纳任务书 2.1 推荐栈）

| 层 | 选型 | 本机验证 |
|---|---|---|
| 桌面 UI | Python + PySide6 | Python 3.12.10 可用（≥3.11） |
| 应用/领域逻辑 | Python 3.12、Pydantic v2 | pip 26.2.1 可安装 |
| Test IR | JSON + JSON Schema Draft 2020-12 | 无额外依赖 |
| 本地数据库 | SQLite + SQLAlchemy 2.x + Alembic | 无额外依赖 |
| DBC 解析 | 优先评估 cantools，输出本项目 NetworkModel | P2 评估 |
| Native Host | C++17 x64（MSVC），官方头文件到位后编译 | P0-02 确认编译器 |
| UI/Host IPC | Windows Named Pipe + 长度前缀 JSON | 标准库可用 |
| 测试 | pytest（unit/contract/integration/e2e 分层） | 待安装 |
| 打包 | P1 不打包；产品化阶段评估 PyInstaller | — |
| AI Provider | OpenAI-compatible 抽象 + SecretStore | Windows Credential Manager 待实现 |

## 备选方案与否决理由

- **Web 前后端（Electron/浏览器）**：否决——任务书明确禁止未经批准改用 Web 架构；本项目需近桌面交互与设备 IPC。
- **Tauri/Electron**：引入 Node 运行时与额外攻击面，桌面 Qt 方案更贴合工程软件形态。
- **ctypes 直调 DLL（Python 侧）**：否决——架构红线，UI/AI 进程不得直接加载厂商 DLL。

## 目录结构

采纳任务书 2.2 建议树：`src/zlg_ai_test_engine/{app,ui,application,domain,plugins,infrastructure,resources}` + `schemas/` + `native/zlgcan_host/` + `plugins/` + `tests/` + `docs/` + `scripts/`。分层隔离要求：domain 不依赖 Qt、protocol 插件不碰 DLL、parser 不碰设备、LLM 不执行工具动作。

## 后果

- P1 起按此结构建仓；任何变更须新增 ADR 说明原因/替代项/风险/迁移成本。
- `.gitignore` 需补充：`vendor_sdk_local/`、`__pycache__/`、`.venv/`、IDE 文件（P1 启动时一并提交）。
- 厂商二进制永不入库（P0-06 合规约束）。

## 待确认

- PySide6 版本锁定与许可证（LGPL，运行时动态链接可接受）在首次依赖提交时记录。
