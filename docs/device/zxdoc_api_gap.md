## 3. 结论（对 1.1 版本 Adapter 的可执行边界）

### 3.1 可凭手册**先行接口设计**（仅限占位 / Mock，全部标 V，不宣称"已支持"）

1. **能力面（形状）可定**：`启停测量 / 报文发送 / 接收回调 / 仿真 message 激活 / DBC 信号读写 / UDS 诊断调用 / 标定信号读写 / 关联数据库` 八类外部能力的**语义边界**来自 p130（D 级），可据此在 `mock_adapter` 侧建立同名语义的占位接口与能力开关，用于 UI/流水线先行联调。
2. **工程文件处理可先行**：ZCP（配置-only、库依赖原路径）与 ZCPC（含库、可移植）差异已明确（p10，D 级），可先实现两者的识别与解析策略。
3. **集成形态可先行**：接口入口为 ZXDoc 内嵌窗口（`帮助-ZXDoc 接口` / `帮助-XIL 接口` / `帮助-zlgcan 开发库`；`仿真-脚本/脚本说明`），说明 1.1 版按"**驱动/调用已安装的 ZXDoc + 独立外部进程**"架构设计，而非把 ZXDoc 当可链接库。
4. **语言选型可先行**：第三方 API = C++/Python（p130、p2）→ 1.1 优先 Python 绑定；C# 仅在 zlgcan 层可用（p132、p2）。

### 3.2 **必须等厂商实体材料**（不得凭手册摘要实现假 API）

1. **任何具体函数名、参数、返回值、回调注册方式**（M1/M3/M4）：手册只有能力清单，无一签名（T13）。实现具体调用 = 制造假 API。
